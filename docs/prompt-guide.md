# Claude Code 잘 쓰는 법 — 프롬프트 가이드

> 2026-08-23 작성. 온비드 공매 분석 하네스 프로젝트 기준 예시 포함.

## 핵심 원리 5가지

1. **목표 + 조건 + 완료 기준**을 한 번에 주면 되묻지 않고 끝까지 간다.
2. **"뭐가 문제인지"만 말하면 진단**, **"고쳐줘"라고 하면 수정**. 구분해서 말할 것.
3. 큰 작업은 **먼저 계획을 보자고** 하면 방향이 어긋난 채 오래 달리는 걸 막는다.
4. 작업이 맞는지 **검증까지 시키면** 품질이 확 올라간다.
5. 반복되는 지시는 **CLAUDE.md나 메모리에 저장**시키면 매번 말할 필요가 없다.

## 상황별 프롬프트 템플릿

### 1. 분석 작업 시킬 때 (이 프로젝트 기준)

```
공매 분석해줘.
- 지역: 경기도 화성시
- 유형: 아파트, 최저입찰가 5억 이하, 유찰 2회 이상
- 투자 조건: 목표 수익률 15%, 최대 투자금 3억
- 완료 기준: 상위 3개 물건 최종보고서까지
```

조건을 빼먹으면 Phase 0에서 되물어야 해서 왕복이 늘어난다. 처음부터 다 주는 게 가장 빠르다.

### 2. 큰 작업 전에 계획부터 보고 싶을 때

```
~~를 하고 싶어. 바로 실행하지 말고 계획만 먼저 보여줘. 계획 승인하면 시작해.
```

(또는 Shift+Tab으로 Plan Mode를 켜면 강제된다.)

### 3. 결과를 못 믿겠을 때 / 검증시킬 때

```
방금 만든 보고서의 숫자들이 원본 데이터(_workspace/01_search_results.json)와
일치하는지 다시 검증해줘. 불일치가 있으면 고치지 말고 먼저 보고해.
```

data-verifier 에이전트를 만든 이유. "검증해줘" 한 마디가 사고를 막는다.

### 4. 문제 상황을 물어볼 때 (수정 vs 진단 구분)

```
이 스크립트가 에러 나. 원인만 분석해서 알려줘. 아직 고치지 마.
```

vs.

```
이 에러 원인 찾아서 고치고, 다시 실행해서 성공하는 것까지 확인해줘.
```

### 5. 실수를 반복하지 않게 만들 때 (제일 강력함)

```
방금 그 실수, 다시 반복하지 않게 CLAUDE.md 변경 이력에 원인과 해결책을 기록해줘.
```

"회차선택 버그" 기록이 좋은 예. 기록된 교훈은 다음 세션의 Claude가 읽고 같은 실수를 안 한다.

### 6. 세션이 끝날 때 / 이어서 하고 싶을 때

```
오늘 한 작업을 커밋하고, 다음에 이어서 할 일을 docs/worklog/에 남겨줘.
```

다음 세션에서:

```
worklog 읽고 지난번 작업 이어서 해줘.
```

### 7. 애매하게 시키고 싶을 때는 판단 기준을 위임

```
어떤 방식이 좋을지 네가 판단해서 진행해.
단, 되돌리기 어려운 작업(삭제, 커밋, 외부 전송)은 하기 전에 물어봐.
```

## 피해야 할 패턴

- ❌ "알아서 잘 해줘" (한 번에) — 조건 없이 시키면 추측으로 채워지고, 나중에 다시 하게 된다.
- ❌ 한 메시지에 서로 다른 작업 5개 — 하나 끝나고 다음 것. 또는 "순서대로 해줘"라고 명시.
- ❌ 결과만 보고 넘어가기 — "테스트/실행해서 확인했어?"라고 물으면 증거를 보여준다.
